# 待追蹤事項顯示「原句：能回調了嗎／命中：稍等」

## 現象

列表上出現對不起來的一列：

```
原句：能回調了嗎
命中：稍等
```

看起來像系統把「能回調了嗎」判成了等待詞 —— 但那句話裡沒有任何一個詞表的詞
（`稍等、等等、等一下、等下、晚點、稍晚、稍後、之後提供、再提供、再給你、
再傳、我去問、我問一下、確認後、查一下、等我`）。

## 先排除「詞表被改過」

`matchKeyword()` 是**子字串比對**（`mb_strpos($text, $keyword) !== false`），
所以命中的詞一定出現在原句裡。「能回調了嗎」這五個字裡找不到「稍等」——
不論設定頁的詞表被改成什麼，這句都不可能命中「稍等」。

**那個詞必然來自另一則訊息。** 這是判斷的起點。

## 為什麼看截圖會以為是同一句

待追蹤事項是**整個客戶群共用一筆**（`findOpenByGroupAndSource($groupId, $source)`
查的是群組層級，不是逐則訊息）。所以那個「稍等」可能是幾小時前、
甚至前一天在同一個群裡說的 —— 翻最近兩則訊息當然找不到。

列表上原本**看不到開單時間**，而「等多久」是從 `wait_at`（最後一次重新計時）
起算的。於是畫面給的所有線索都指向「這筆是剛剛那句開的」：

```
原句：能回調了嗎      ← 被換掉的（客人 12:59 說的別的話）
等多久：19 分鐘        ← 從 12:59 起算
命中：稍等            ← 真正開單那句的，可能是幾小時前
```

## 起因：`resetWait()` 被兩種語意共用

`CustomerFollowupService::advance()` 處理「這個對話已經有一筆活著的事項，
對方又說話了」。最後那條路是**客人說了別的話**（不是等待詞）：

```php
// 修正前
if ($followup->isWaiting() && $followup->isFromCustomer()) {
    $this->repository->update($followup, $this->resetWait($messageId, $text, $followup->matched_keyword));
}
```

這條路的用意只是**把計時往後推**（需求方決策 3：對話正熱的時候不要插進來問
當班人員「要不要追蹤」，客人其實就在線上）。但它借用了 `resetWait()`，
而那一支會寫這些欄位：

| 欄位 | 寫入的值 | 對不對 |
|---|---|---|
| `wait_at` / `remind_count` / `last_reminded_at` | 重新計時 | ✅ 這條路要的 |
| `wait_text` | **客人最新說的那一句** | ❌ |
| `matched_keyword` | 刻意傳舊的 `$followup->matched_keyword` | ❌ 跟上面那欄對不起來 |
| `telegram_message_id` | 最新那則 | ❌ 引用會指到不相干的訊息 |

於是原句被換成「能回調了嗎」，命中的詞還是最初那句的「稍等」。

**沒有誤判，只是顯示錯了** —— 這筆事項從頭到尾都是對的，錯的是它說自己是
怎麼來的。

## 修法

拆成兩支，名字各自說清楚語意：

- `resetWait($messageId, $text, $keyword)` —— 只給「這一句本身就是等待詞」用
  （目前唯一的呼叫點是「又拖一次」）。原句與命中的詞一起換，**兩者必然同源**。
- `pushBackWait()` —— 只寫 `wait_at` / `remind_count` / `last_reminded_at`。
  不碰原句、命中的詞、引用的訊息 id。

## 教訓

> ⚠️ **一支「重設」方法被兩種語意共用，就是遲早要拆的。**
> `resetWait()` 的名字只說了「重新開始等」，沒說「連同原句一起換」——
> 第二個呼叫端想要的只有前半，於是傳了一個舊的 `$keyword` 進去「保留」它。
> **那個「傳舊值進去以免被覆蓋」的動作本身就是訊號**：
> 要保留的欄位根本不該出現在這次更新裡。
>
> ⚠️ 「原句」這類欄位要回答的是**那筆資料為什麼存在**，不是「最後發生了什麼」。
> 計時可以一直往後推，但「哪一句話讓我們開始等」是不變的事實。

## 連帶補的：列表要看得到開單時間

資料修好之後，畫面仍然缺一個關鍵線索 —— **這筆是什麼時候開的**。
`created_at` 後端早就送了（`FollowupResource`），只是前端沒畫。

補上「開單時間」欄，並在「等多久」的表頭加 `title` 說明它是從最後一次
對方說話起算。兩欄並排看就分得出「這筆剛開」與「這筆拖很久、只是中途
有人講過話」—— 原本這兩種在畫面上長得一模一樣。

## 異動檔案

- `app/Services/CustomerFollowupService.php` — `advance()` 改走 `pushBackWait()`；
  新增該支；`resetWait()` 的 docblock 寫明只給等待詞那條路用
- `resources/views/admin/followup/index.blade.php` — 新增「開單時間」欄、
  「等多久」表頭加說明
- `public/js/followup.js` — 畫那一欄；空狀態的 colspan 9 → 10
- `resources/lang/{tw,cn,en}/followup.php` — `col_opened_at`、`col_waited_hint`

已經存在的那幾筆**沒有一起修**（只能靠人看出哪些對不起來）。

「這筆最初是因為那個詞開的，後來客人又說過別的話」。
