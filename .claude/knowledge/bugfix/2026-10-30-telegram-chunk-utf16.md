# 規章明明放得下卻被切成兩則（分段門檻用錯單位）

> 需求方 2026-10-30：「規章傳送的分段的字數怪怪的，我下面這段不應該被分為
> 兩則訊息才對。」附了一份 LV 三、四方系統介紹。

## 症狀

那份規章被小幫手切成兩則連發，但它其實一則就放得下。

量出來：

| 量法 | 數字 |
|---|---|
| 位元組（`strlen`）| 7,200 |
| 字元（`mb_strlen`，code point）| 3,993 |
| **UTF-16 code unit** | **4,046** |

Telegram 單則上限是 **4,096 UTF-16 code unit** —— 4,046 明明放得下。

## 兩個錯疊在一起

### 1. 門檻設太保守（3,500）

`CHUNK_SIZE` 原本抓 3,500，註解寫「留餘裕給**標題那幾行**與頁碼」。
但抬頭在同一天稍早已經被拔掉了（需求方：「上面不要標規章名稱和專案」）——
那 596 個單位的餘裕變成純粹浪費，而這份規章就落在 3,500 與 4,096 之間。

⚠ **拔掉一個東西時，要回頭看有沒有別的地方是為了它才留的餘裕。**

### 2. 計數單位從一開始就不對（這個比較嚴重）

`split()` 用 `mb_strlen()` 比對門檻，那算的是 **code point**；
Telegram 算的是 **UTF-16 code unit** —— BMP 外的 emoji 一個算**兩**單位。

兩者對純中文／英數一樣，但 emoji 一多就會分岔。方向是危險的那一邊：

> `mb_strlen` **低估**真實長度 → 「算起來沒超過」但「實際送不出去」，
> 而 Telegram 超過上限是**整則失敗**，不是截斷。

舉例：4,000 個 emoji 的規章，`mb_strlen` 算 4,000（看起來安全），
實際是 8,000 單位 —— 門檻只要調到 4,000 以上就會整則發不出去。

所以**不能只是把 3,500 改成 4,096**，得連量法一起換掉。

⚠ 這個專案的 `TelegramChatService` 早就為了 entity offset 處理過同一件事
（`utf16Length()` / `sliceUtf16()`，見
[[2026-10-13-telegram-mention-offset]] 那一類的註解）。
**同一個坑在同一個專案踩第二次** —— 下次碰 Telegram 的長度／位置，
先問「這個數字是什麼單位」。

## 改法

`config/constants.php`：

| 改前 | 改後 |
|---|---|
| `CHUNK_SIZE => 3500` | `MAX_LENGTH => 4096`（Telegram 硬上限）<br>`PAGE_RESERVE => 16`（頁碼那幾個字）|

`RegulationCommandService::split($content, $max, $reserve)`：

1. **先用完整的 `$max` 判斷整份放不放得下** —— 放得下就一則發完，
   那時候不會掛頁碼，所以不該先扣 `$reserve`。
   ⚠ 先扣再判斷的話，長度落在 4,081～4,096 的規章會白白被切成兩則。
2. 真的要分段時，每段才用 `$max - $reserve`。
3. 長度一律走新的 `utf16Length()`。
4. 取前綴改走新的 `sliceToUtf16Limit()`。

## ⚠ 修的過程中自己又寫出一個缺陷（已修）

`sliceToUtf16Limit()` 第一版是「照 code point 取，量出來超過就按超出量往回砍」：

```php
$count -= ($length - $limit);   // ← 在 emoji 多的時候砍過頭
```

4,000 個 emoji（8,000 單位、上限 4,080）第一刀從 4,000 退到 **80**，
結果一份規章被切成 **6 則、長度 166／326／646／1286／2566／3046** 的碎訊息。
每則都沒超過上限、也沒掉字，但群組裡會被刷一排短訊息 ——
**「沒有壞掉」不等於「對」**。

改成二分搜尋找最長的合格前綴（上界取 `min($limit, 字數)`，
因為超過 $limit 個 code point 的前綴一定超過 $limit 單位）。
同一份輸入從 6 則變 2 則。

## 驗證

把需求方那份原文存成檔案，用反射叫私有方法跑（不碰 DB、不發訊息）：

| 輸入 | 結果 |
|---|---|
| **需求方那份（4,046 單位）** | **1 則**（修之前是 2 則）、內容沒掉字 |
| 剛好 4,096 個英數 | 1 則 |
| 4,097 個英數 | 2 則 [4086, 23] |
| 2,048 個 emoji（＝4,096 單位）| 1 則 |
| 2,049 個 emoji（＝4,098 單位）| 2 則 [4086, 24] |
| 4,000 個 emoji（＝8,000 單位）| 2 則 [4086, 3926]（回退法那版是 6 則）|
| 2 萬字條列式（有換行）| 3 則，都從換行切 |
| 2 萬字完全沒換行 | 5 則 |
| 空字串 | 1 則、不會爆 |

每一則都把頁碼一起算進去再量，確認**實際送出的長度**都 ≤ 4,096。

⚠ **沒有真的發到 Telegram 驗過**（本機沒有專案與規章資料）。
