# AI 回覆宣稱「已請專員調閱您的設定紀錄」

> 線上實際回給客人的：
>
> 「老闆，手續費這段已請專員**調閱 10/13 的設定紀錄比對**，再麻煩您稍候一下 -A」
>
> 需求方：「這段是 AI 回的，不能說請專員調閱，**我們不能去拿客人的資料**」

## 為什麼是問題

不是語氣問題，是**說了一件我們不會做、也不該做的事**：

- **不是事實** —— 系統只是開了一張求助單，沒有人去翻客人的設定紀錄
- **是承諾** —— 客人會以為真的有人在比對，等不到就變成我們失信
- **更糟的是它暗示我們在翻客人的後台** —— 客人的資料不是我們可以隨便去看的，
  主動告訴他「我們去調閱了」等於自己講出一件不該發生的事

## 模型為什麼會這樣寫

`AUTO_REPLY.WAIT.PROMPT` 裡有一條「**可以順著他問的內容講，不要每次都一樣的
句型**」—— 那是為了避免罐頭感。但模型「順著講」的方式就是**自己腦補一個處理
動作**：客人問手續費，它就寫「調閱設定紀錄比對」；連 `10/13` 這個日期也是它
自己補的。

⚠ 一般化：**要模型「講得自然一點」就等於給它編故事的空間。** 凡是會被客人
看到的生成文字，都要明講「哪些事不能寫」，不能只說「寫得自然」。

## 修法：prompt ＋ 護欄兩層

這個專案自己的註解早就寫過「**護欄比 prompt 可靠**」
（`AUTO_REPLY.STRANGER.BLACKLIST` 那段），所以兩層都做。

### 1. prompt 明講（正反例都給）

```
- 不要描述我們會對他的資料做什麼。只說已經轉給專員、請他稍候就好，
  不要寫「調閱您的紀錄」「查看您的設定」「比對您的後台資料」這類話 ——
  我們不會去拿客人的資料，講了既不是事實，也會讓客人以為我們在翻他的後台
  好的寫法：「老闆，手續費這段已經請專員為您確認，再麻煩您稍等一下」
  不好的寫法：「老闆，手續費這段已請專員調閱 10/13 的設定紀錄比對…」
- 不要自己補上日期、單號、金額這些細節 —— 客人沒講的就不要寫進去
```

正反例比單純「不要寫 X」有效得多（「不要道歉開頭」那次就是這樣修的）。

### 2. 黑名單護欄

`AUTO_REPLY.WAIT.BLACKLIST` 加上動作詞：

```
'調閱', '調取', '調出', '查閱', '翻閱', '調資料', '調紀錄'
```

命中就整句作廢，退回公版 `FALLBACK`（「已經為您轉給專員確認，稍候回覆您 🙏」）。

⚠ **只擋「動作」，不擋「紀錄」「設定」本身。** 客人自己問「我的設定怎麼了」
時，回覆裡出現那兩個字是正常的 —— 擋了會把好句子一起誤殺。

### 3. 同一條規則也放進 `FOLLOWUP.ASK_CUSTOMER`

那一支也是對客的自由文字（問客人之前答應要給的東西）。只修出事的那一支，
下次就會在另一支重演 —— 這個專案已經踩過好幾次「同一條規則實作在幾個地方
就會各自長歪」。

## 驗證

護欄（`OpeningSanitizer::sanitize($text, 'AUTO_REPLY.WAIT')`）：

| 句子 | 結果 |
|---|---|
| 線上那句（含「調閱」） | **擋下** → 退回公版 ✓ |
| 「已經請專員為您確認，再麻煩您稍等一下」 | 通過 ✓ |
| 「**您的設定**這部分已請專員確認」 | 通過 ✓（沒有誤殺） |

prompt（本機 CLI 實測三句）：

| 客人問 | 模型回 |
|---|---|
| 10/13的手續費怎麼跟我算的不一樣 | 老闆，10/13 手續費這段已經請專員為您確認，再麻煩您稍等一下。 |
| 我昨天的訂單為什麼沒有入帳 | 老闆，昨天這筆訂單已經請專員為您確認，再麻煩您稍等一下。 |
| 無法送單會是未加入IP嗎 | 老闆，送單這部分已經請專員為您確認，再麻煩您稍等一下。 |

三句都還是「順著問題講」（提到手續費／訂單／送單），但不再描述處理動作，
也沒有憑空補出來的日期。
