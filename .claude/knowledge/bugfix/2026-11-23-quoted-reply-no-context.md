# 客人引用我方的提問來回答，小幫手卻回「已經請專員為您確認」

> 需求方 2026-11-23：「這邊是客服人工去詢問進度，然後對方回應明天處理，
> 不應該回覆請專員確認才對。」

## 線上實際經過

| 時間 | 誰 | 內容 |
|---|---|---|
| 13:11 | 我方同仁（人工，署名 -E） | 「老闆您好，請問目前超商通道設定上還順利嗎，有什麼需要協助的部分嗎？」 |
| **23:52** | 客人（**引用**上面那一則） | 「明天設定」 |
| 23:52 | 小幫手 | 「老闆，明天設定這部分已經請專員為您確認，再麻煩您稍等一下。 -A」 |

客人是在**回答我們**，不是在**問我們**。回一句承接話術 ＋ 開一張求助單，
兩件事都是錯的。

## ⚠⚠ 根因：模型手上只有「明天設定」四個字

不是模型判斷力不好 —— **是它什麼都沒看到**。

```php
// config/auto_reply.php
'context' => [
    'limit'   => 6,
    'minutes' => 15,   // ← 只看 15 分鐘內
],
```

同仁那則問話是 **13:11**、客人 **23:52** 才回 —— 隔了 11 小時，
`buildHistory()` 撈不到。模型收到的就只有「明天設定」，前後文一片空白。

那四個字單獨看**確實**判斷不出來，所以模型照 schema 的指示填了
「分不出來就 unclear」⇒ 轉人工 ＋ 回承接話術。**它做的是對的事，
錯在我們給的資訊不完整。**

## ⚠ 而我們其實早就有那段資訊，只是沒送出去

客人是**引用**我方那一則回的。收訊時就解析過了：

```php
// TelegramChatService，收 inbound 時
$replyToSender = $this->buildSenderName($replyMsg['from'] ?? []);
$replyToText   = $replyMsg['text'] ?? ($replyMsg['caption'] ?? '');
```

這兩欄一直存在 `telegram_message.reply_to_sender` / `reply_to_text`，
**但只拿來給後台對話窗顯示，從來沒進過送給模型的脈絡。**

## 修法：把引用的那一則接到脈絡最前面

```
（客人這一則是在回覆下面這一則）我方：老闆您好，請問目前超商通道設定上還順利嗎… -E
客人 西瓜汁：明天設定
```

⚠⚠ **這一則刻意不受 `context.minutes` 限制。**
客人指著哪一則，那一則就是他的上下文 —— **隔多久都一樣**。
15 分鐘那條線是給「最近在聊什麼」用的，不適用於明確的引用。

### 「是我方說的」要講出來

只貼內容的話，模型仍得自己猜那句是誰說的 ——
而「客人在回答我方的提問」與「客人在追問另一個客人說的話」，
該給的反應完全不同。

⚠ 判斷方式是 **`reply_to_message.from.id` 對上目前這支 Bot**：
人工回覆與自動回覆都是透過同一支 Bot 送出去的，所以
「from ＝ Bot」就代表客人指著的是我方的話。

⚠ 要用 `botService->getBotId()`（上面已經 `switchBotToken()` 切到該群組
的 Bot），不是設定檔的預設 token —— 否則非預設 Bot 的群組會全部
判成「不是我方的」。

⚠ **這件事只有 webhook 那一刻比得出來**，所以是用 Job 參數傳下去的，
不是從 DB 撈（`telegram_message` 只存了引用的文字與暱稱，沒存
「那一則是誰的」）。

### 另外補在判斷規則裡

脈絡補上去只是讓模型**看得到**，還要讓它知道**怎麼判**。
`buildSchema()` 的 `intent` 說明加了一條：客人這一則若是在回覆我方
先前的提問（我方問「設定上還順利嗎」、他回「明天設定」「好」「處理中」），
那是 `chat` ——「他在回答我們」不是「他在問我們」，
不要填 `question`／`unclear`，也不要轉人工。

## 改了哪些檔

| 檔案 | 動作 |
|---|---|
| `app/Services/TelegramChatService.php` | 判斷引用的那則是不是我方發的；派 Job 時把引用帶上 |
| `app/Jobs/AutoReplyJob.php` | 多一個 `$quote` 參數（⚠ `(array)` 轉型，擋舊 Job 反序列化成 null） |
| `app/Services/AutoReplyService.php` | 🆕 `withQuote()`：把引用接到脈絡最前面 |
| `app/Services/AutoReply/ClaudeCodeMatcher.php` | `intent` 的說明加上「在回答我們 ＝ chat」 |

沒有 migration（欄位本來就有）、沒有新路由、沒有新權限。

## 驗證到哪

`withQuote()` 六種情況（交易外的純函式測試）：

| 情況 | 結果 |
|---|---|
| 線上那一案（引用我方 11 小時前的提問） | 脈絡多一行「（客人這一則是在回覆下面這一則）**我方**：老闆您好…」 |
| 引用的是另一位客人說的話 | 標成「**客人 阿明**」，接在原脈絡最前面 |
| 引用的那則已經在脈絡裡 | **不重複貼**（2 行進、2 行出） |
| 引用的是一張圖（沒有文字） | 不動脈絡 |
| 沒有引用 | 不動脈絡 |
| 引用的內容有換行 | 壓成一行（同 `buildHistory()` 的理由） |

⚠⚠ **模型那一側驗不到**：laradock 容器沒有裝 `claude` CLI，
所以「補上脈絡之後它會不會真的改判 `chat`」**沒有實測過**。
這次修的是「把它該看到的東西給它」—— 判斷仍然是模型做的。

⚠ 要觀察的是：同樣的情境（客人引用我方提問來回答）下次還會不會回承接話術。
