# 傳圖前的圖片編輯器：裁切、塗鴉、馬賽克（v3.94 已實作，**前端未實測**）

> 需求方 2026-11-20：「我 Telegram 對話這邊上傳圖片，我還有一次的預覽，
> 我想要可以讓他裁切、塗鴉這些動作，跟 Telegram 對話一樣。」
>
> 工具範圍（同日確認，**全選**）：裁切＋旋轉／畫筆／馬賽克・塗黑／
> 箭頭・方框・文字。

## 傳送視窗改版（需求方 2026-11-20 附 Telegram 截圖：「做成這樣」）

```
┌────────────────────────────┐
│  傳送圖片                     │
│                              │
│   ┌──────────────┐ [🔄][🗑]  │
│   │                      │   │
│   │   圖片（點一下＝編輯）  │   │
│   │                      │   │
│   └──────────────┘        │
│                              │
│   說明文字                    │
│   ────────────────── 😊      │
│                              │
│  新增              取消  傳送  │
└────────────────────────────┘
```

| 元素 | 行為 |
|---|---|
| **點圖片** | 開編輯器（裁切／塗鴉／馬賽克） |
| 🔄 | 換掉這一張（重選檔案） |
| 🗑 | 移除這一張；移到沒有了就關掉視窗 |
| 新增 | 再挑一張加進來（往下疊，可捲動） |
| 說明文字 | 整組共用一段，**掛在第一張上** —— 既有送出邏輯本來就是這樣，跟 Telegram 一致 |
| 😊 | 沿用既有的表情選單（`emoji.js`） |

需求方確認**不做**的兩個（參考圖上有，但我們用不到）：

- **「壓縮圖片」勾選**：圖片一律當圖片傳（走現有 `ajax-send-image`）
- **右上角 ⋮**：裡面是「分別傳送」這種我們用不到的選項；
  替換與刪除已經在每張圖自己的角落了

⚠ **編輯完不直接送出**，一定要退回這個視窗 ——
送到客戶群組是收不回來的，編輯過的圖更需要再看一眼。

⚠ **手機版同一套版面**（需求方指定），用 `modal-fullscreen-sm-down`
讓它在小螢幕撐滿；按鈕尺寸照既有的 `btn-sm` 慣例不另外放大。

### ⚠⚠ 這會收掉「貼上之後出現在輸入框上方」的舊流程

現在有**兩套**待傳機制：從按鈕選檔會開確認視窗（單檔），
而貼上／拖曳的圖會堆在輸入框上方的小縮圖列（`pendingFiles`，多檔）。

新視窗本身就是「多張圖 ＋ 一段說明」的容器，功能完全涵蓋舊的縮圖列 ——
兩套並存只會讓「我的圖到底在哪裡」變成一個要想一下的問題。
所以**貼上與拖曳也改成開這個視窗**（跟 Telegram 一樣），
舊的縮圖列整個移除。

⚠ 這是**使用習慣的改變**，上線要讓客服知道：以前貼上之後是在輸入框打字，
現在是在跳出來的視窗裡打。

## ⚠⚠ 馬賽克是這次最重要的工具，不是裝飾

客服截圖常常整個後台畫面都拍進去，裡面有**別的客戶的帳號、金額、手機**。
現在只有兩條路：不傳（客人得不到說明），或傳了把別人的資料一起送出去。

所以遮擋要做兩種：**馬賽克**（看得出有東西但認不出內容）與
**純色塗黑**（完全蓋掉）。敏感欄位用塗黑，不想嚇到客人的用馬賽克。

## 工具列

| 工具 | 行為 |
|---|---|
| 裁切 | 拖拉選框（四角＋四邊手把），框外變暗；套用後畫布換成裁切結果 |
| 旋轉 | 90° 一下，連按四次回到原點 |
| 畫筆 | 自由畫線，可選顏色與粗細 |
| 箭頭 | 從按下的點拉到放開的點，畫一支實心箭頭 |
| 方框 | 拉一個空心矩形（圈住整塊區域用） |
| 文字 | 點一下開輸入框，打完貼上去；顏色與畫筆共用 |
| 馬賽克 | 拉一個區域，那塊像素化 |
| 塗黑 | 拉一個區域，填滿純色 |
| 復原 | 退掉最後一筆（**不是整張重來**） |
| 重設 | 回到剛選進來的原圖 |

顏色給固定幾個（紅／黃／綠／藍／白／黑），不做調色盤 ——
客服要的是「圈起來看得見」，不是配色。

## 技術作法：全部自己寫，不引第三方

⚠ **這個專案沒有 npm／webpack**（`package.json`、`webpack.mix.js` 都不存在，
CLAUDE.md 那段已經過時），第三方是「下載檔案丟 `public/vendor/`」
（flatpickr、pusher 都是這樣）。

裁切如果用 Cropper.js 會省掉拖拉手把的功夫，但那要先把檔案下載進
`public/vendor/` —— 而**我沒辦法替你下載**。為了一個拖拉選框讓整件事
卡在「等人去抓檔案」不划算，所以**六種工具全部自己寫**，零依賴。

### 畫布分兩層

| 層 | 內容 | 什麼時候重畫 |
|---|---|---|
| 底層 canvas | 原圖 ＋ 已經確定的每一筆標註 | 操作堆疊有變動時 |
| 上層 canvas | 正在拖曳中的那一筆（箭頭、方框、選框） | 每次 pointermove |

⚠ **分層是為了「拖曳時不要每一幀都重畫整張原圖」**：4000×3000 的截圖
每幀重畫一次會掉到十幾 fps，拉箭頭會頓。

### 復原靠「操作堆疊」而不是圖片快照

每一筆存成 `{type, points, color, width}` 這種小物件，復原就是
`pop()` 之後重畫。

⚠ **不要存 `ImageData` 快照**：一張 4000×3000 的快照是 48MB，
存十步就把瀏覽器吃光了。

⚠ 例外是**裁切與旋轉**：它們會改變畫布尺寸，沒辦法只用重畫表示。
作法是把「套用前的狀態」整個存成一張離屏 canvas 當新的底圖，
並把堆疊清空 —— 所以**裁切之後不能復原到裁切前的標註**，
這一點要讓使用者知道（按鈕上寫「裁切後會固定目前的標註」）。

### 座標要換算

畫布用**原圖尺寸**（才不會把圖畫糊），顯示時用 CSS 縮到視窗大小。
滑鼠／手指座標是顯示座標，每一筆都要乘上 `naturalWidth / clientWidth`。

⚠ 這是最容易出錯的一段：縮放比例算錯的話，畫筆會跟手指**差一段距離**，
而且離中心越遠偏得越多。

### 觸控

一律用 **Pointer Events**（`pointerdown/move/up`），滑鼠與手指同一套程式碼。
後台是 PWA、對話視窗本來就有滑動回覆手勢（`swipe-reply.js`），
所以手機上一定會有人用。

⚠ 編輯區要 `touch-action: none`，否則手指一畫整個頁面就跟著捲動。

## ⚠ 輸出：編輯完可能比原檔還大

`canvas.toBlob()` 重新編碼，**PNG 截圖畫幾筆之後常常更大**，
而上傳上限是 5MB（`MAX_IMAGE_BYTES`）。

作法：
1. 原本是 JPEG 就輸出 JPEG（`quality 0.92`），原本是 PNG 就輸出 PNG
2. 輸出後量一次大小，超過上限就**自動改成 JPEG 0.85 再試一次**
3. 還是超過就告訴他「編輯後的圖太大，請先裁切一部分」，而不是讓他按了發送才失敗

⚠ 檔名沿用原檔（`photo.png` → `photo.png`），格式真的換了才改副檔名 ——
客人那邊看到的檔名要跟他收到的內容對得起來。

## 實作後的補充

### 檔案

| 檔案 | 內容 |
|---|---|
| `public/js/telegram-chat/image-editor.js` | 編輯器本體，約 700 行，零依賴 |
| `public/css/telegram-chat-image-editor.css` | 編輯器 ＋ 傳送視窗圖卡的樣式 |
| `public/js/telegram-chat/input.js` | 傳送視窗改成多檔；**刪掉**舊的縮圖列（`pendingFiles` 那一整套） |

⚠ `image-editor.js` **必須排在 `input.js` 之前**載入（blade 裡有註解）——
點圖片時要看得到 `T.openImageEditor`。

⚠ CSS 走 `@section('css')`，不是 `styles` —— layout 裡的 yield 名稱是 `css`。

### ⚠ 語系 key 是組出來的

工具列是迴圈產生的，`t('editor_' + tool.key)` —— 所以 `editor_pen`、
`editor_crop` 這些在 PHP 檔裡 grep 不到字面。語系檔那邊已經加了註解，
**不要當成沒用到刪掉**。

### ⚠ 馬賽克的預覽是半透明方框，不是真的馬賽克

拖曳預覽畫在上層 canvas，而馬賽克要讀「底下現在長什麼樣」才算得出來 ——
上層是透明的，讀不到。所以拖曳時先用半透明白框示意，**放開才真的套用**。

### ⚠ 馬賽克在 `ops` 裡的順序有意義

它是疊在「當下畫面」上的操作：先畫箭頭再馬賽克，箭頭也會被糊掉 ——
那是對的，重畫時照順序跑就會重現同樣結果。

## ⚠⚠ 上線測試第一輪抓到的（2026-11-20，需求方實測）

### 點圖片完全沒反應 —— 掛錯全域物件，而且被靜靜吞掉

這個專案的全域物件叫 **`TgChat`**（`state.js` 建的），我寫成
`window.TelegramChat = window.TelegramChat || {}` —— **自己建了一個沒人看的
物件**，把 `openImageEditor` 掛在上面。

更糟的是呼叫端寫成「沒有就不做事」：

```js
if (!file || !T.openImageEditor) { return; }   // ← 錯誤在這裡被吞掉
```

結果是點下去完全沒反應、console 也沒有任何東西。

兩個都修了：名字改成 `TgChat`，而且**載不到編輯器時要在視窗上講一句**
（`editor_failed`），不要靜靜 return。

> 教訓：`if (!something) return` 這種寫法在「something 本來就該存在」的
> 場合是**把 bug 藏起來**，不是防禦。

### 「換一張」「刪除」兩顆按鈕

需求方：「我如果要重傳，我就直接關閉 modal 就好，何必多此一舉。」

- **「換一張」整個拿掉**：要換那一張，刪掉再按「新增」是同一件事
- **只有一張圖時連「刪除」也不印**：那時刪除＝關掉視窗，而取消鈕就在旁邊
- 兩張以上才出現刪除鈕（那時它真的有用：拿掉其中一張）

語系的 `btn_replace_image` 也一起刪掉，不留死 key。

### 視窗裡每張圖一樣大

需求方：「大張就讓他縮小，如果要塗鴉，就讓操作者自己放大塗鴉就好。」

`height: 240px` ＋ `object-fit: contain`（手機 200px）。
**`contain` 不是 `cover`**：預覽要看得到整張，裁切是編輯器裡的事。

## ⚠⚠ 第二個「完全沒反應」：CSS 放錯 section

改掉全域物件名稱之後，需求方回報**還是沒反應**。用瀏覽器實際查才看到：
`telegram-chat-image-editor.css` **根本沒載入**，編輯器因此是 `position: static`、
長在頁面最底下（`y: 855`）—— DOM 在、函式有跑，就是看不到。

原因：我用 `@section('css')`，而**layout 的 `@yield('css')` 位在 `<style>`
標籤裡面** —— `<link>` 塞進 `<style>` 當然失效。

⚠ 這件事 `shared-file/index.blade.php` 的註解早就寫過了：

> layout 的 `@yield('css')` 位在 `<style>` 標籤內，放 `<link>` 會失效，
> 因此與 task-board 一樣把樣式表載在 content 開頭

照慣例改成在 `@section('content')` 開頭載入就好了。
**既有頁面的註解是有人踩過的坑，動手前該先看。**

## 視窗長寬高固定（需求方 2026-11-20：「不要又要滑動」）

整個 modal 變成固定高度的 flex 欄：

| 區塊 | 行為 |
|---|---|
| `.modal-dialog` | `max-width: 560px`、`height: 80vh`（手機交給 `modal-fullscreen-sm-down`） |
| `.modal-body` | `display: flex; flex-direction: column; min-height: 0; overflow: hidden` |
| `#tg-send-file-preview` | `flex: 1 1 auto; min-height: 0; overflow-y: auto` |
| 單張圖 | `.tg-send-item:only-child` 撐滿整個圖片區，`object-fit: contain` |
| 多張圖 | 每張固定 200px，上下排列，超過才捲 |

⚠ **`min-height: 0` 不能省**：沒有它 flex 子元素不會縮，圖片照樣把 body 撐開。

⚠ **拿掉了 `modal-dialog-scrollable`**：那個 class 會讓 Bootstrap 自己管
`modal-body` 的捲動，跟這套 flex 版面打架。
