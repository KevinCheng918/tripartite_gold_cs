# 這句話是講給誰聽的（`not_for_us`，v4.13，已完成）

> 需求方 2026-11-24：「要 AI 判斷一下上下文吧，不能寫死的。」
> 「不是講給我們的就靜默，整則都是外人的話還是要判斷 —— 因為有時候是
> 對方跟對方的人講說可以跟我們求助，這樣只會標他們的人，不該被靜默。」

客戶群組裡不是只有我們跟一位客人：**對方公司的人會當著我們的面彼此講話**
（把同事叫進來看、交代同事去辦、問同事好了沒）。那些話我們聽得到，
但不是在問我們 —— 插話進去等於憑空生出一件客人沒問過的事。

緣由、踩過的坑與實測結果都在
[[2026-11-24-tag-with-words-same-message]]（這份只記最終長相）。

## 怎麼判

```
webhook 收到訊息
  ├─ 算出這則 tag 了誰（entities）、每個是不是我方 → 存進 telegram_message.mentions
  └─ 派 AutoReplyJob（帶 mentions）
        └─ 模型看三樣東西判 intent
             ├─ <這則訊息 tag 了誰>      這一則的 tag（事實）
             ├─ <前面的對話>             每行後面帶〔這則 tag 了：…〕
             └─ <客人的問題>             要判的那一句
                  └─ not_for_us → SILENT：不回、不開單、不標記已回覆
```

**判準是「這句話在等誰回答」，不是「他 tag 了誰」**：

| 他說的 | 在等誰回答 | 結果 |
|---|---|---|
| 「龍 所以改好了嗎？」 | 龍（對方的人） | `not_for_us`，完全不回 |
| 「@小陳 你先去後台看一下」 | 小陳 | `not_for_us` |
| 「阿明 這個你跟客服說一下」 | **要我們接手** | 照常判（question／request） |
| 「@小陳 這個帳號不能登入」 | 我們 | 照常判 |
| 「請問費率怎麼算」 | 我們 | 照常判 |

## 三個不能動的地方

1. **不標記已回覆** —— 判錯時那則還掛在未回覆上，未回覆告警會響、客服接手。
   這是唯一的安全網（見 [[2026-11-08-silent-black-hole]]）。
2. **不開求助單** —— 對方同事之間的每句話都開單，支援群組會被雜訊淹掉。
3. **餵給模型的 tag 名單只寫事實**（叫什麼、是不是我方），不寫結論。
   寫成「所以他在跟自己人講話」就等於把判斷做回硬規則了。

## `mentions` 欄位

`telegram_message.mentions`：`[{label, ours}]`，沒 tag 任何人時是 null。

⚠ **非存不可**：`text_mention`（對方沒有 username）文字裡根本沒有 `@`，
存進 `content` 之後誰都看不出「龍」是在叫人。脈絡要帶這份標注模型才判得準
（實測：沒有標注時 11/13 那個案例只判得到 `unclear`）。

⚠ 2026-11-24 之前的舊訊息這欄是 null，脈絡就不加標注，不影響可用性。

## 怎麼測

```bash
php artisan auto-reply:test "所以改好了嗎？" --tag=龍
php artisan auto-reply:test "這個帳號不能登入" --tag=@sl0168888
php artisan auto-reply:test "麻煩看一下" --our-tag=@cs_mei
```

`--tag` 是對方的人、`--our-tag` 是我們的人（線上這份名單是 webhook 從
`entities` 算的，終端沒有那個東西所以要手動指定）。

## 已經移除的東西

| 移除的 | 原本做什麼 |
|---|---|
| `TelegramChatService::isTalkingToOutsiders()` 等 8 支 private method | 第四道閘門：整則都是 tag 外人就擋、擋完 60 秒靜默 |
| `config('auto_reply.tag_outsider_silence')` | 靜默窗秒數 |

⚠ **不要再把它們加回來。** 規則分不出「他在問同事」與「他叫同事來跟我們講」，
而猜錯的方向是「客人真的在求助卻被靜音」。
