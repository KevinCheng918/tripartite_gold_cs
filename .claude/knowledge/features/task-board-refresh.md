# 任務看板的刷新

> 需求（2026-10-30）：「任務版要有一個刷新功能，我就不用每次有人更新
> 就要重新整理一次網頁。」

**狀態：已完成（v3.50，2026-10-30）。**

## 做了兩件事，不是一件

需求句子裡有兩個訴求，而且要分開滿足：

| 訴求 | 做法 |
|---|---|
| 「要有一個**刷新功能**」 | 操作列一顆「刷新」鈕 |
| 「不用**每次有人更新**就要重新整理」 | 每 30 秒自動刷新（安靜模式）|

⚠ **只做按鈕不夠**：使用者的痛點是「別人改了我不知道」，
一顆要自己按的按鈕只是把 F5 換成滑鼠點擊。

⚠ **只做自動刷新也不夠**：有時候就是想立刻看到結果（例如剛請人改完）。
而且**按鈕本身是在告訴使用者「這一頁會更新」** —— 看不到任何控制項的話，
沒有人會相信畫面是新的。

⚠ 所以按鈕旁邊有一行小字「自動刷新中，上次 HH:MM」——
只放按鈕的話使用者會以為非按不可，反而比原本更焦慮。

## 幾乎不用寫新東西

`loadBoard()` 本來就是 AJAX 重載（而且會帶上目前的篩選條件），
所以主要工作是**加一個「安靜模式」**與**判斷什麼時候不准刷**。

```js
function loadBoard(quiet) {
    …
    if (!quiet) { showBoardSkeleton(); }
    …
}
```

⚠ **自動刷新一定要走安靜模式**：每 30 秒閃一次骨架，看板會像壞掉一樣，
而且正在看的那一欄會跳掉。

⚠ **安靜模式下請求失敗不要覆蓋畫面**：原本的 `error` 會把五欄換成
「載入失敗」。自動刷新踩到網路斷一下就把使用者正在看的看板清空，
比不刷新糟得多 —— 他什麼都沒做，資料卻不見了。資料留著、下一輪再試才對。

## ⚠ 重點全在「什麼時候不准刷」

自動刷新會把五欄的 HTML 整個換掉。在使用者正在操作的時候做這件事，
等於把他做到一半的事情弄掉 —— **「幫他省一次重新整理」的好處遠小於這個壞處**。

`canAutoRefresh()` 的五道關卡：

| 條件 | 為什麼 |
|---|---|
| `document.hidden` | 分頁在背景，沒人在看。刷了只是白打 API，而且會一直累積 |
| `$('.modal.show').length` | 新增／編輯任務、異動紀錄、封存清單、各種確認框都開著不能動 |
| `boardDragging` | 換掉 HTML 會讓拖曳中的卡片消失在手上 |
| `#side-panel-body` 裡有 `.tox-tinymce` | 描述正在用 TinyMCE 編輯，內容還沒存 |
| `activeElement` 是 INPUT／TEXTAREA／SELECT | 正在打字（關鍵字、留言、inline 編輯）|

⚠ **「側邊面板開著」不算正在操作**：面板內容不是 `renderBoard()` 畫的
（它畫 `#side-panel-body`），刷新不會動到它 —— 為此停掉自動刷新太嚴格，
而「開著面板看卡片」正是最需要背景更新的場景。

⚠ **`boardDragging` 不能用 `dropColumn !== null` 代替**：
游標拖到欄位外面時 `dropColumn` 會被清成 null，但手上還抓著卡片。

⚠ **`boardDragging = false` 要放在 `onEnd` 的第一行**：
下面任何一個 `return`（拖回原處、狀態沒變）都會讓旗標卡在 true，
自動刷新就**從此永久停擺，而且完全不會報錯**。

## 間隔走 config

`config/constants.php` 的 `TASK.BOARD_REFRESH_SECONDS = 30`。

⚠ **不要調太短**：每次刷新是一趟 `ajax-board`，而那支會撈五欄全部的卡片
（含專案、站台、指派人員的關聯）。這是給客服「別人改了我看得到」用的，
不是即時同步 —— 30 秒已經足夠，10 秒只是把查詢量變三倍。

⚠ 改了 `config/` 要跑 `php artisan optimize`，否則新的值不生效。

## 相關檔案

| 檔案 | 說明 |
|---|---|
| `config/constants.php` | `TASK.BOARD_REFRESH_SECONDS` |
| `resources/views/admin/task-board/index.blade.php` | 刷新鈕與狀態小字；`loadBoard(quiet)`；`canAutoRefresh()`；`markRefreshed()`；`boardDragging` 旗標（Sortable 的 `onStart`／`onEnd`）|
| `resources/lang/{tw,cn,en}/task_board.php` | `action_refresh`／`refresh_last` |

## 明確不做

- **不做 WebSocket／SSE 真即時** —— 這個系統沒有常駐的推送基礎設施，
  為了看板架一套不成比例。30 秒輪詢對客服看板足夠。
- **不做「有更新」的紅點提示再讓使用者決定要不要刷** ——
  那要先比對前後資料差異，而安靜刷新本身已經沒有干擾了。
- **不做開關**（讓使用者關掉自動刷新）—— 五道關卡已經避開所有會干擾的情況，
  多一個開關只是多一個要解釋的東西。真的有人要求再說。
